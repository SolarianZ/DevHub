# DevHub 部署与运行指南

本文面向本地安装、发布、启动与上线后校验场景，说明 DevHub 的运行约束、目录布局、发布方式与基础运维检查项。

## 1. 部署原则

- DevHub 是本机单用户守护进程，默认按“每个 OS 用户一个实例”运行。
- Hub 仅应监听回环地址（`127.0.0.1`、`localhost`，实现也可额外使用 `::1`）。
- 客户端必须从 `hub.json` 动态发现 `httpBaseUrl` 与 `wsUrl`，禁止假设固定端口或固定 WebSocket 路径。
- Hub 启动后会生成新的会话 token；重启或重新部署后，客户端需要重新读取 `token.txt`。

## 2. 运行时目录与配置

### 2.1 默认数据目录

默认数据根目录遵循系统约定：

- Windows：`%LOCALAPPDATA%/DevHub/`
- macOS：`~/Library/Application Support/DevHub/`
- Linux：`$XDG_DATA_HOME/DevHub/`（未设置时为 `~/.local/share/DevHub/`）

默认目录结构如下：

```text
<devhubRoot>/
├── runtime/
│   ├── hub.json
│   └── token.txt
├── apps/
│   ├── definitions/
│   └── instances/
└── logs/
```

### 2.2 环境变量覆盖

- `DEVHUB_RUNTIME_DIR`：覆盖运行时目录本身（即 `hub.json`、`token.txt` 所在目录）。
- `DEVHUB_APPDEFS_DIR`：覆盖应用定义目录。
- `DEVHUB_APPINST_DIR`：覆盖实例镜像目录。
- `DEVHUB_LOG_DIR`：覆盖日志目录。

说明：

- `DEVHUB_RUNTIME_DIR` 仅覆盖运行时目录，不应被当作固定端口或固定地址的替代手段。
- 如果使用环境变量覆盖路径，应在启动 Hub 前设置，并确保目录对当前用户可读写。

### 2.3 关键文件

`hub.json` 是客户端发现入口，至少应关注：

- `protocolVersion`
- `httpBaseUrl`
- `wsUrl`
- `tokenFile`
- `runtimeTuning`

`token.txt` 保存 bearer token，文件权限应限制为当前用户可访问。

## 3. 发布

建议使用 Release 配置发布 Host：

```bash
dotnet publish src/DevHub.Host/DevHub.Host.csproj -c Release -o ./artifacts/devhub
```

发布目录中会包含 `DevHub.Host.dll` 及其依赖文件。若只做本地开发联调，也可直接使用 `dotnet run`；正式交付或固定产物验证时，优先使用 `dotnet publish` 的输出目录。

## 4. 启动

### 4.1 使用默认目录启动

```bash
dotnet ./artifacts/devhub/DevHub.Host.dll
```

### 4.2 使用显式目录启动

```bash
export DEVHUB_RUNTIME_DIR=/path/to/devhub/runtime
export DEVHUB_APPDEFS_DIR=/path/to/devhub/apps/definitions
export DEVHUB_APPINST_DIR=/path/to/devhub/apps/instances
export DEVHUB_LOG_DIR=/path/to/devhub/logs
dotnet ./artifacts/devhub/DevHub.Host.dll
```

Windows PowerShell 示例：

```powershell
$env:DEVHUB_RUNTIME_DIR = "C:\DevHub\runtime"
$env:DEVHUB_APPDEFS_DIR = "C:\DevHub\apps\definitions"
$env:DEVHUB_APPINST_DIR = "C:\DevHub\apps\instances"
$env:DEVHUB_LOG_DIR = "C:\DevHub\logs"
dotnet .\artifacts\devhub\DevHub.Host.dll
```

启动成功后，应看到运行时目录中生成 `hub.json` 与 `token.txt`，实例镜像落在 `DEVHUB_APPINST_DIR`（或默认 `apps/instances/`）下，并且日志目录开始写入 `devhub-*.log`。

## 5. 上线后校验

### 5.1 校验发现文件

启动后先检查 `hub.json`：

- `httpBaseUrl` 不应包含末尾斜杠。
- `wsUrl` 应为绝对 WebSocket URL，且不应包含末尾斜杠。
- `httpBaseUrl` 与 `wsUrl` 应指向回环地址。
- `tokenFile` 应为绝对路径，且文件存在。

### 5.2 最小健康检查

以下示例中的 `DEVHUB_HTTP_BASE_URL` 与 `DEVHUB_TOKEN` 需要替换为 5.1 中检查到的实际值，或先导出为同名环境变量。

```bash
curl -sS -X POST "$DEVHUB_HTTP_BASE_URL/rpc" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $DEVHUB_TOKEN" \
  -H "X-DevHub-Protocol: 1" \
  -H "X-DevHub-ClientId: OpsDiag" \
  -H "X-DevHub-ClientSessionId: 00000000-0000-0000-0000-000000000010" \
  -d '{"jsonrpc":"2.0","id":"ops-ping-1","method":"hub.ping","params":{}}'
```

如需先从运行时目录读取 `hub.json` 与 token，请直接使用 [`运维排障手册`](./运维排障手册.md) 中“3.1 读取 `hub.json` 与 token”一节的最小诊断脚本。

### 5.3 WebSocket 校验

如果部署后需要验证事件链路，连接 `hub.json.wsUrl` 后，第一条消息必须发送 `hub.ws.authenticate`；在认证成功前发送其他请求或通知，连接会被拒绝。

## 6. 当前运行约束

- Hub 重启后，内存态 pending invocation 与 request waiter 不保留。
- 调用投递语义为 at-least-once，租约过期可能导致重投递。
- WebSocket 事件当前不支持重放，断线窗口内事件可能丢失。

相关背景与后续规划请参考 [`docs/DevHub协议与开发规划.md`](./DevHub协议与开发规划.md)。

## 7. 运行与回滚建议

- 发布后若发生重启、替换或回滚，客户端都应重新读取最新的 `hub.json` 与 `token.txt`。
- 若出现鉴权、协议版本、实例发现或调用超时问题，请优先参考 [`运维排障手册`](./运维排障手册.md)。
- 若需要执行部署后的最小回归验证，可运行：

```bash
python3 tests/test_runner.py --smoke --no-header
```
